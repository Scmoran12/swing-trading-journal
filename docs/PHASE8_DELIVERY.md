## Implemented

- Owner-only `/readiness` and GET `/api/readiness` inspect actual local PostgreSQL role/catalog/settings metadata. Checks cover distinct restricted login/group roles, extra role membership, loopback listener, supported PostgreSQL version, forced owner RLS, absence of public table/security-definer execution grants, and separation of credential/financial authority. Output contains safe check codes/statuses only, not connection strings, passwords, role/owner/account names, paths or journal values. No financial/state-changing command is invoked. Normal session authentication can still update its existing last-seen heartbeat.
- The readiness page retains dark Hebrew RTL and explains that filesystem/migration-hash checks require the separate local command. Native market, spending controls, actual scheduling/recovery, human desktop receipt, conditional iPhone and backup/restore acceptance remain conservative fixed pending/blocked/deferred statuses. They do not ingest local evidence or claim that a local PASS completes those gates. No enable/accept action exists.
- `npm run local:doctor` / `npm run local:doctor -- --test` explicitly load the existing private configuration. They check matching loopback DB host/port/name, three separate configured login identities, private config/data locations, existing Unix owner/modes (Windows ACLs remain manual), project secret.env absence, and exact installed migration hashes/missing/newer schema. DB inspections use BEGIN READ ONLY, bounded connection/query timeouts and ROLLBACK; no setup, migration, chmod/ACL write, journal read/write, cleanup or backup action. A bad path/config halts before connecting. JSON stdout is sanitized. Exit0 means local checks passed,1 a failed check/config,2 unresolved manual local ACL verification; none means release acceptance.
- Runtime config loading now rejects mixed DB targets, shared migration/runtime/auth usernames, URL query credential overrides and private paths in the project/OneDrive. `--test` launcher refuses absent/mismatched/non-test settings rather than using inherited personal connections. Existing private configuration is preserved; setup/recovery is not an update mechanism. These guards do not attest to the broker's account billing settings.
- Private-image storage rechecks the resolved root outside the real project/OneDrive, including ancestor symlink escapes; Unix root must retain current-user ownership/private mode. Doctor reports failures without changing permissions. Windows ACL evidence remains required, separate from a Linux test.
- Source version0.8.0 is consistent in package, authenticated footer, health metadata and doctor/readiness output. Health remains configuration-only, not a connectivity/acceptance check. Source excludes generated reports/builds/dependencies and private data/credential file patterns. Runbooks cover startup/update, schema-compatible code recovery, incidents and outstanding Windows acceptance.

No new migration: delivered0001–0007 and dependency versions are unchanged.
