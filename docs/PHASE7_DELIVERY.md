## Delivered behavior

- `/analytics` replaces the placeholder, retaining Hebrew RTL and dark default. Inclusive date filters use **Asia/Jerusalem final effective SELL date**. A closed trade contributes its entire lifetime result, including earlier buys, ADDs and partial exits. This is neither period realized SELL P&L nor portfolio return. Open trades and closed trades outside the period have separate exclusion counts.
- The authoritative SQL replay owns fee-inclusive net P&L and the frozen gross first-purchase-batch initial risk. The new read model consumes those projections; it does not implement a second FIFO ledger. Decimal arithmetic uses isolated precision48, half-even rounding; screen formatting is presentation only. Metrics: count, wins/losses/breakeven, net/mean USD P&L, win rate, profit factor and mean closed R with R coverage. Zero belongs in denominators. No losses means undefined profit factor; no trades means unavailable means/rates. Missing/nonpositive R excludes only R metrics. Estimated fees stay labeled; separate account dividends/taxes/fees are excluded from trade P&L.
- ADD and no-ADD segments retain original R; first-batch emotions count each closed trade once. Mixed first-batch emotions use MULTIPLE, later ADD emotions do not relabel entry. UNKNOWN/DECLINED/MULTIPLE are coverage, not directional evidence. Groups below20 trades have an insufficient-sample label. All groups are descriptive; there is no causal, diagnostic or ranking claim.
- Entry adherence is narrowly measurable: maximum first-batch fill price versus the **pinned approval entry ceiling**, and initial batch quantity versus approved quantity. Coverage/exclusions are explicit. New drafts do not rewrite original approval comparisons. There is no overall discipline score or guess about intent, stop management or whether an acknowledged deviation was justified.
- Source table links to each owned trade, with chronological closure, ledger revision, net P&L/R, calendar-day duration, ADD and fee provenance. Decorative bars duplicate text values; tables have captions/headers and keyboard-focusable overflow regions. Real browser/keyboard/narrow-screen acceptance is still unrun.
- **Drawdown, TWR, MWR and exchange-session duration remain unavailable.** The ledger lacks complete historical portfolio valuation at exact flow boundaries and verified session coverage. Closed P&L or a current manual mark cannot supply those missing data. No equity/return curve is fabricated.

## Read model and durable review contract

New migration **0007_journal_analytics.sql** adds read indexes, `analytics_input`, weekly review jobs/commands/events and a bounded security-definer command. Delivered0001–0006 are byte-identical. Runtime can read owned rows under forced RLS, but cannot directly modify tables. Snapshot creation and reads use the same owner advisory lock as financial commands. Inputs pin `CLOSED_TRADES_V1`, DB capture time, period and the committed journal-command revision excluding READ_NOTIFICATION. Current reports use today's corrected projection, not a reconstruction of past knowledge. Saved review inputs remain immutable historical snapshots. Unknown metric versions are rejected rather than silently reinterpreted.

The read model queries the complete cohort, not the manual workspace's500-row UI window. Up to10,000 closed trades per report are supported; larger cohorts fail explicitly and require a narrower range. No silent truncation. Review history displays the most recent100; total storage is capped at500 requests, with8 pending/paused. The fixed caps have no automatic archival/deletion workflow.

Creating a review requires the displayed journal revision and sharing acknowledgment. Exactly identical pending inputs deduplicate; request keys replay exact results, and changed bodies conflict. The owner chooses any period (seven days for a weekly review). A durable AWAITING_CODEX job does not imply it was dispatched. The packet is manually copied into an existing native Codex included-usage chat. No API/model invocation, bridge call, task, quota inspection or paid fallback exists.

Only aggregate metrics, cohort/ADD coverage and entry-comparison counts enter the packet. **Emotion aggregates default off** and require explicit selection. No symbols, trade IDs, trade timestamps, individual emotions, notes, screenshots, account balances/credentials or financial mutation commands are shared. The local snapshot retains the owned source cohort to reproduce results, including recorded emotions regardless of packet opt-in. The UI's separate local snapshot export explicitly includes trade details/emotions; it is not the minimal AI-sharing packet or a full backup. The stored SHA-256 binds the immutable database input, not the exact reduced packet text.

Response import uses the existing bounded plain-text review schema with the separate JOURNAL_ONLY_WEEKLY_REVIEW scope. It checks exact fields, job/hash, known unique fact IDs, categories/count/text bounds and owner/revision, plus explicit human review acknowledgment. Unknown references/extra approval or market fields reject. Structural validation **does not establish semantic correctness, model identity, subscription enforcement, causality or genuine Codex provenance**; all imported narrative is labeled unverified and cannot approve/mutate any financial fact. Plain React text rendering does not execute imported HTML/Markdown. Pauses for usage/auth/bridge persist as user reports, block packet transfer/import and require explicit resume. Any financial/planning command after capture makes pending and completed reviews stale; late submissions are quarantined STALE_RESULT. Reading an inbox item does not stale them. Concurrent state changes fence on row revision.
